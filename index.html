2. Tổng quan Lab

Tên chuẩn hóa: Đấu nối Mạch vật lý và Lập trình Giao tiếp với Cảm biến & Cơ cấu chấp hành cơ bản trên Breadboard.

Chủ đề kỹ thuật chính: Phân tích tín hiệu Digital (Nút nhấn), Điều khiển Digital (LED rời), Thu thập dữ liệu môi trường (Cảm biến nhiệt ẩm DHT11), Hiển thị thông tin cục bộ (Màn hình LCD qua chuẩn I2C), Kỹ thuật Điện trở kéo (Pull-down) và Khử rung phím (Debounce) bằng phần mềm.

Vị trí trong hệ thống: Tầng 2 (Lớp Giao tiếp phần cứng cơ bản).

  • Tính kế thừa: Kế thừa kỹ năng vận hành IDE, Cổng COM và nạp code từ Lab 1. Tuy nhiên, ở Lab này, chúng ta tạm gác mạng WiFi/Cloud sang một bên để đối mặt trực tiếp với các định luật Vật lý và Điện tử.
  • Chuẩn bị cho tương lai: Một hệ thống IoT sẽ vô nghĩa nếu không có dữ liệu. Dữ liệu từ cảm biến DHT11 thu thập chuẩn xác ở Lab này sẽ là "Hàng hóa" (Telemetry Data) cực kỳ quan trọng để bạn bơm lên Đám mây (Blynk, MQTT, Firebase) ở các Lab 3, 4, 7 sau này.

3. Bản chất Học thuật: Điện tử gặp gỡ Lập trình

Code sai có thể xóa viết lại, Cắm sai sẽ BỐC KHÓI!

Trọng tâm của Lab 2 KHÔNG PHẢI là thao tác gõ mã nguồn, mà là thao tác KẾT NỐI VẬT LÝ và xây dựng TƯ DUY LOGIC TRẠNG THÁI. Bạn đang phải giải quyết 3 vấn đề rất "cơ học" của thế giới thực:

  1. Sự mơ hồ của Điện áp (Floating State): Nút nhấn cơ học bản chất chỉ là 2 miếng kim loại chạm nhau. Khi bạn nhả tay ra, mạch điện bị hở, chân vi điều khiển biến thành một cái ăng-ten thu nhiễu sóng radio từ môi trường và nhảy số loạn xạ (0-1-0-1). Làm sao để ghim nó về mức 0V một cách kiên cố khi không ai bấm? Đó là bài toán của Điện trở kéo (Pull-down Resistor).
  2. Lò xo cơ học và Hiện tượng Dội phím (Bouncing): Khi bạn bấm nút 1 cái, lò xo bên trong nảy lên nảy xuống ở mức độ vi mô, khiến vi điều khiển (với tốc độ hàng triệu vòng/giây) lầm tưởng bạn vừa bấm 100 lần. Làm sao để lọc bỏ tiếng ồn cơ học này? Đó là bài toán của Khử rung phím (Debounce) bằng độ trễ phần mềm.
  3. Đa ngôn ngữ Giao tiếp (Protocols): Mạch ESP8266 phải nói chuyện với 3 thiết bị bằng 3 ngôn ngữ khác biệt hoàn toàn: Nói với LED bằng điện áp 3.3V thuần túy (Đóng/Cắt), nói với DHT11 bằng chuỗi xung thời gian (1-Wire Protocol), và nói với Màn hình LCD bằng địa chỉ ô nhớ mạng (I2C Protocol).

4. Mục tiêu giảng dạy / học tập

Sau khi hoàn thành Lab 2, sinh viên phải CHỨNG MINH ĐƯỢC các năng lực:

  1. Thao tác chuẩn xác trên Breadboard: Nối nguồn chung, mass chung, quy hoạch đường dây gọn gàng, tuyệt đối tránh rủi ro ngắn mạch (Short Circuit).
  2. Phân biệt rạch ròi giữa ký hiệu chân in trên vỏ mạch (VD: D1, D2) và Mã số GPIO thực tế bắt buộc dùng trong trình biên dịch C++ (VD: GPIO5, GPIO4).
  3. Thiết lập và Bảo vệ mạch điện: Tính toán dùng điện trở 220Ω để cản dòng chống cháy LED, dùng điện trở 10kΩ để ghim mức logic an toàn cho nút nhấn.
  4. Định tuyến thiết bị I2C: Sử dụng công cụ I2C Scanner để tự động quét và thu thập địa chỉ Hex (Address) của màn hình thay vì gõ bừa.
  5. Xử lý ngoại lệ (Exception Handling): Bẫy và xử lý êm đẹp lỗi NaN kinh điển khi cảm biến DHT11 bị mất kết nối hoặc bị ép đọc quá nhanh.

5. Kiến thức nền sinh viên cần hiểu rõ

  • NodeMCU Pinout (Ánh xạ Chân): Vi điều khiển bên trong ESP8266 chỉ hiểu ngôn ngữ "GPIO". Khi nhà sản xuất in chữ D6 lên bo mạch, nó tương ứng với GPIO12. Nếu bạn cắm dây vật lý vào D6 nhưng trong code bạn viết int ledPin = 6;, mạch sẽ câm điếc hoàn toàn. Quy tắc kỹ sư: Luôn mở hình ảnh bảng NodeMCU Pinout kế bên khi lập trình!
  • Chuẩn giao tiếp I2C: Đây là một mạng lưới siêu gọn nhẹ, chỉ cần 2 dây: SDA (Serial Data - Truyền dữ liệu) và SCL (Serial Clock - Đồng bộ nhịp xung). Bạn có thể nối song song hàng chục thiết bị I2C (Cảm biến ánh sáng, gia tốc kế, màn hình...) vào chung 2 dây này. Vi điều khiển sẽ đóng vai trò "Lớp trưởng", gọi đúng tên "Địa chỉ Hex" (Ví dụ: 0x27 hoặc 0x3F) thì thiết bị mang ID đó mới được phép lên tiếng trả lời.
  • Căn bệnh NaN (Not a Number): Là kết quả báo lỗi của hàm C++ khi nó yêu cầu cảm biến DHT11 trả về nhiệt độ nhưng cảm biến im lặng (do lỏng dây data, hoặc do bị hàm loop() ép đọc quá nhanh liên tục khiến chip cảm biến bị treo). Trong toán học máy tính, NaN không thể mang đi cộng trừ nhân chia. Nếu đem biến `NaN` in thẳng ra LCD, hệ thống sẽ hiển thị rác hoặc lỗi bộ nhớ.

7. Phân tích Kiến trúc Hệ thống & Luồng Dữ liệu

Hệ thống Lab 2 được chia làm 2 mô-đun phần cứng độc lập, sau đó mới tích hợp lại bằng phần mềm C++:

Mô-đun 1: Xử lý Tín hiệu Số (Digital Input/Output Logic)

[Ngón tay bấm Nút] --(Đóng mạch 3.3V)--> [Chân Input D7] --(Code C++ bẫy sườn & Toggle cờ)--> [MCU ESP8266] --(Xuất áp 3.3V)--> [Chân Output D6] --> [LED Sáng]

Mô-đun 2: Thu thập & Hiển thị Dữ liệu Môi trường (Protocols)

[Nhiệt độ môi trường] --> [Sensor DHT11] --(Chuỗi bit 1-Wire)--> [Chân Input D5] --> [MCU dịch mã ra số thực] --(Giao thức I2C qua D1, D2)--> [LCD 1602 vẽ ký tự]

Nguyên lý Tối thượng: GND CHUNG (Common Ground). Toàn bộ các module cắm trên Breadboard, cho dù tiêu thụ điện áp 3.3V hay 5V, đều PHẢI nối chung vào một đường GND (Mass âm). Nếu mạch bị lệch Mass, tín hiệu điện áp sẽ không có hệ quy chiếu chuẩn (0V), dẫn đến dữ liệu bị rác và mạch nhiễu điên cuồng.

8. Phân tích Sơ đồ phần cứng (BẢO VỆ CHÁY NỔ)

9. Các tham số Cần Cá nhân hóa (Đừng Copy Mù Quáng)

Hardware mỗi người mỗi khác!

Mã nguồn C++ sinh ra là để phục vụ cho Sơ đồ cắm dây của bạn, không phải ngược lại. Việc Copy Paste thiếu suy nghĩ sẽ đẻ ra hàng loạt lỗi logic.

  • LiquidCrystal_I2C lcd(<NHẬP_ĐỊA_CHỈ_I2C>, 16, 2);: Khai báo đối tượng màn hình. Con số địa chỉ I2C phổ biến nhất thường là 0x27. Tuy nhiên, một số lô hàng LCD từ nhà sản xuất dùng chip PCF8574A sẽ có địa chỉ là 0x3F. Nếu nạp code xong màn hình sáng đèn nhưng không lên chữ, bạn bắt buộc phải chạy đoạn code I2C Scanner để tìm ID đích thực của nó. (Tài liệu PDF gốc ghi placeholder 0x00 là một cái bẫy khiến mạch chết cứng).
  • Mapping Chân (Pin): Nếu tay bạn lỡ cắm cái đèn LED vào lỗ D1 trên mạch, bạn phải chủ động vào phần khai báo sửa code thành int ledPin = 5; (Vì D1 tương ứng GPIO5). Mọi sự lười biếng không tra bảng Pinout đều phải trả giá bằng việc code đúng nhưng đèn không sáng.

10. Quy trình Thực hành Từng bước (Phương pháp Phân rã Module)

Tư duy Kỹ sư: KHÔNG BAO GIỜ cắm mọi thứ cùng một lúc!

Lắp LED xong -> Test code LED. Cắm Nút nhấn -> Test code Nút. Cắm LCD -> Test chữ Hello World. Cắm DHT11 -> Test in ra Serial Monitor. Thành công hết các hàm lẻ tẻ mới gộp lại thành 1 file bự. Làm sai nguyên tắc Isolate (Cô lập và Bắt bệnh) này, khi toàn bộ mạch không chạy bạn sẽ không biết bắt đầu gỡ dây từ đâu.

1 Giai đoạn 1: Mạch Logic Bập bênh (Toggle Button & LED)

  1. Rút cáp USB. Cắm LED, Nút nhấn và 2 con Điện trở (220Ω và 10kΩ) lên Breadboard theo Bảng sơ đồ Mục 8. Kéo nối dây VCC/GND từ NodeMCU sang cấp nguồn cho Breadboard.
  2. Dùng mắt soi lại một lượt: Có cọng dây nguồn đỏ nào đang chập thẳng vào dây Mass đen không? Ổn thỏa thì cắm cáp USB vào máy tính.
  3. Copy khối code Mô-đun 1 (Ở phần 13 bên dưới), thay đổi thông số chân nếu cần, rồi nạp vào vi điều khiển.
  4. Nghiệm thu: Bấm ngón tay vào nút dứt khoát 1 cái rồi nhả ra -> LED bật sáng và giữ nguyên trạng thái. Bấm cái nữa -> LED tắt. (Bắt bệnh: Nếu đưa tay lại gần chưa chạm nút mà đèn đã tự chớp loạn xạ, bạn cắm lỏng điện trở 10k kéo Mass rồi).

2 Giai đoạn 2: Khám phá Địa chỉ Mạng I2C (I2C Scanner)

  1. Rút cáp USB. Nối 4 dây của màn hình LCD I2C vào mạch (VCC -> VIN, GND -> GND, SDA -> D2, SCL -> D1). Cắm cáp lại.
  2. Mở IDE, vào Menu File > Examples > Wire > i2c_scanner. Nạp trực tiếp đoạn code có sẵn này vào mạch.
  3. Mở Serial Monitor (Chỉnh Baudrate 9600 hoặc 115200 tùy yêu cầu của code). Lấy bút ghi lại con số định dạng Hex hiện ra (Ví dụ: 0x27 hoặc 0x3F).

3 Giai đoạn 3: Tích hợp Toàn Hệ thống

  1. Rút cáp USB. Cắm nốt cảm biến DHT11 vào chân D5.
  2. Cắm điện. Copy khối code Mô-đun 2 (Tổng hợp) ở Phần 13 vào IDE.
  3. SỬA BẪY MÃ NGUỒN (Quan trọng): Đổi các đoạn có ngoặc nhọn `<...>` trong hàm khai báo chân cắm và hàm LiquidCrystal_I2C thành con số thực tế của bạn (Ví dụ: 0x27). Nếu quên sửa, IDE sẽ báo lỗi đỏ lòm khi Compile.
  4. Nhấn Upload nạp code.
  5. Nghiệm thu: Màn hình LCD in ra "Nhiet do" và "Do am" kèm ký hiệu độ C (°) cực xịn. Thổi hơi nóng hoặc áp lòng bàn tay vào DHT11, chờ 2-4 giây để thấy số biến đổi tịnh tiến. Thử bấm Nút nhấn, đèn LED vẫn phải bật/tắt bình thường không bị đơ giật.

11. ⚠️ BẮT BUỘC: VƯỢT ẢI CÂU HỎI TRƯỚC KHI XEM CODE

Tấm vé thông hành mở khóa Code C++:

Mentor/Giảng viên có quyền yêu cầu sinh viên gập máy tính lại và trả lời 6 câu hỏi này trước khi cho phép copy mã nguồn:

  1. Bạn cắm dây đèn LED vào lỗ in chữ D6 trên mạch, nhưng trong code C++ lại bắt buộc phải khai báo int ledPin = 12;. Chữ số 12 này từ đâu chui ra? Bạn phải tra cứu sự ánh xạ này ở tài liệu nào?

// XÓA DẤU NGOẶC NHỌN VÀ ĐIỀN ĐÚNG MÃ GPIO CỦA CHÂN D6 VÀ D7 VÀO ĐÂY!
int ledPin = ;      
int buttonPin = ;   

int switchState = 0;      // Biến chứa điện áp hiện tại của nút (1: Đang đè, 0: Thả ra)
int oldSwitchState = 0;   // Kho lưu trữ điện áp của 1 tíc-tắc trong quá khứ
int lightsOn = 0;         // Cờ (Flag) lưu trạng thái logic của đèn (0: Tắt, 1: Sáng)

void setup() {
    pinMode(buttonPin, INPUT); // Nút nhấn là Nguồn Cấp tín hiệu vào (INPUT)
    pinMode(ledPin, OUTPUT);   // LED là Thiết bị Nhận tín hiệu ra (OUTPUT)
}

void loop() {
    switchState = digitalRead(buttonPin); // Chụp ảnh điện áp tại chân Nút nhấn ngay lúc này

    // THUẬT TOÁN EDGE DETECTION (Phát hiện sườn tín hiệu chuyển mạch):
    // Chỉ chạy code bên trong nếu có sự THAY ĐỔI cơ học (Từ thả -> Bấm, hoặc Bấm -> thả)
    if (switchState != oldSwitchState) 
    {
        delay(50); // THỦ THUẬT DEBOUNCE: Ngủ 50ms để triệt tiêu sóng rung của lò xo cơ học
        
        // Sàng lọc kỹ: Nếu sự thay đổi đó chính xác là hành động "Đang đè nút xuống"
        if (switchState == HIGH) 
        {
            lightsOn = !lightsOn; // Toán tử Đảo logic (!): Nếu đang 0 thành 1, đang 1 lật thành 0
            
            // Xả điện áp vật lý ra chân phần cứng LED dựa theo Cờ logic vừa lật
            if (lightsOn == 1) { digitalWrite(ledPin, HIGH); }
            else { digitalWrite(ledPin, LOW); }
        }
    }
    // GHI ĐÈ Hiện tại vào Quá khứ để vòng lặp tiếp theo có dữ liệu lịch sử để so sánh
    oldSwitchState = switchState;  
}
